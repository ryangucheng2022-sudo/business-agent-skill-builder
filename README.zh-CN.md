# business-agent-skill-builder

[English](README.md) | 简体中文

**把真实业务流程变成可复用的 Agent 技能——而且靠谱。** 一套经过实战检验的方法（含模板与检查清单），把 SOP、表格和审批流程转化成 AI Agent 能以业务级纪律执行的技能：输入输出显式定义、计算可追溯、权限边界明确、人工确认点前置、用真实案例验证。

业务场景里的 Agent 技能翻车，通常不是模型不行，而是没人把边界写下来：Agent 能碰什么、文件冲突时以谁为准、哪些数字必须可追溯、哪一步必须人确认。这个包补的就是这层设计。

## 包里有什么

- `SKILL.md`——方法本身（就是一个 Agent 技能）：从圈定一个窄流程到上线后迭代的 7 步法。
- `references/business-skill-design.md`——适配性测试、最小业务简报、输入/输出契约。
- `references/agent-boundary.md`——权限四级（只读／只起草／确认后写／自主写）、升级确认点、来源优先级、输出风险标签。
- `references/business-skill-template.md`——可直接填空的业务技能 SKILL.md 模板。
- `references/validation-checklist.md`——触发、流程、业务逻辑、资源、案例测试五维清单与「完成」标准。
- `examples/resale-cost-accounting/`——用本方法完整做出的一个微型技能（字段字典、计算规则、异常案例），让你看到成品长什么样，而不是靠想象。

## 谁在用、用它做什么

| 角色 | 典型场景 | 价值点 |
|---|---|---|
| **业务负责人与运营者** | 「每月的成本核算／审批复核／报价分析应该能自己跑」 | 把流程交给 Agent 而不交出判断力：范围保持窄、异常浮出水面而不是被藏起来 |
| **职能专家（财务、供应链、销售运营、人事）** | 把你的公式、清单、复核规则编码下来，让别人（和 Agent）一致执行 | 隐性经验变成有版本的参考文件——字段字典、计算规则、异常案例——不再只活在某个人脑子里 |
| **企业 AI／数字化推进者** | 在各部门推广 Agent 又不能出事故 | 边界框架（权限分级、确认点、来源优先级、风险标签）就是让推广站得住的治理层 |
| **Agent 开发者与顾问** | 给客户或内部平台交付业务技能 | 模板＋验证清单，把「能演示」和「业务敢用」分开：用已知答案的真实案例做测试，是方法内置的一步 |

## 方法一句话版

从一个闭环小任务开始，而不是「部门助理」。收集真实的调用说法和样例文件。动笔之前先定 Agent 边界：读写权限、能碰哪些系统、什么必须人确认。技能结构最小化——规则进 references、确定性计算进 scripts、模板进 assets。指令要写成「如何执行」而非业务科普，内置来源核查、升级与验证。用历史或代表性案例验证（正常、缺字段、来源冲突、异常值、一个有标准答案的真实案例）。上线后从真实使用中迭代，小步快跑。

## 方法总览

全流程七步，每步都有检查点——检查点不过，不进入下一步。

| 步骤 | 输入 | 产出 | 检查点 |
|---|---|---|---|
| 1. 界定工作流 | 一个真实业务流程（SOP、习惯或痛点） | 一个范围收窄的工作流及负责人 | 是否窄到可验证？ |
| 2. 采集实例 | 真实案例，含例外与边界情形 | 技能必须能处理的案例集 | 是否包含失败路径，而不只有顺利路径？ |
| 3. 定义 Agent 边界 | 工作流＋风险点（审批、金额、对外承诺） | 可做 / 禁止 / 升级三张清单 | 先定边界、再动手搭建 |
| 4. 设计技能内容 | 边界＋案例 | 技能大纲：指令、参考资料、模板 | 每个内容块都能回溯到案例或规则 |
| 5. 写业务级指令 | 大纲 | 技能本体：输入、输出、计算、升级点全部显式 | 新人只看这份能否独立执行？ |
| 6. 验证技能 | 第 2 步的案例集 | 逐例通过/失败及失败记录 | 发布前必须过真实案例验证 |
| 7. 从使用中迭代 | 真实使用中发现的纠正 | 更新后的技能＋新增验证案例 | 每条真实纠正都沉淀为一个案例 |

## 用法

把本文件夹放进你的 Agent 平台技能目录，让 Agent 用它来建技能，例如：

> 「用 business-agent-skill-builder，把我们每月的报价评审流程做成一个技能。这是上个月的输入和已批准的输出。」

`examples/` 里有成品的样子可以参照。
